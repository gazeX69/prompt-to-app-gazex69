# MEMORY SYSTEM

## Run Isolation Architecture
To prevent the AI from hallucinating state across different executions, the workspace relies on strict **Run Isolation**.

Every time the orchestration engine triggers a mutation sequence, it generates a unique `run_id`. All cognitive output (patches, replays, simulations) is persisted to `<project-root>/workspaces/<workspace_id>/<run_id>/.orchestration/`.

## Folder Taxonomy
- `p6/patches.json`: Contains the initial, raw contextual grounding generated by the planning engine.
- `p65/replays.json`: Contains the dynamic evaluation matrix. How safe is the `p6` patch against the actual repository at this exact moment in time?
- `p66/simulations.json`: Contains the virtual diffs and syntax evaluations.

## Immutability Rule
Once a run completes, its `.orchestration/` folder is frozen. If the user rewinds history and selects an old `run_id` in the UI, the frontend will accurately hydrate the exact pending patch states from that point in time. You must never script a backend route that retroactively mutates a past run's JSON artifacts.
