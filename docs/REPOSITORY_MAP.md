# REPOSITORY MAP

## 1. Backend Core (`backend/core/`)
- `workspace_scanner.py`: The read-only intelligence parser. Scans folders, extracts symbols via Regex, maps dependency relationships, calculates blast radius.
- `scanner/patch_grounding.py`: The P6/P6.5 cognitive engine. Translates fuzzy patches into hard target coordinates and validates them against live drift.
- `scanner/patch_simulation.py`: The P6.6 execution sandbox. Diff strings in memory, checks syntax balance.
- `scanner/execution_readiness.py`: The P6.7 validation gatekeeper.

## 2. Backend Routes (`backend/routes/`)
- `workspaces.py`: Main router exposing the active tree, artifacts, runs, replays, and simulations to the frontend.

## 3. Frontend Core (`frontend/src/`)
- `stores/workspace.store.ts`: The central Zustand nervous system binding the frontend to the backend orchestration data.
- `api/workspace.api.ts`: API contracts and interfaces. Matches the backend schemas perfectly.

## 4. Frontend Observability Panels (`frontend/src/panels/`)
- `WorkspaceOverview.tsx`: The macro dashboard. (Telemetry, Execution Readiness, Timeline).
- `RepositoryExplorer.tsx`: The structural intelligence map. (File trees, operational heat mapping).
- `FileInspector.tsx`: The micro cognition shell. (Deep file intelligence, symbols, regions, pending patches, simulated diff overlays).

## 5. Live State Boundaries
- `root/workspaces/`: The location of actual user code.
- `root/workspaces/<id>/<run_id>/.orchestration/`: The immutable cognition data generated by the AI for a specific run.
